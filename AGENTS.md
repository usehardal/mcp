# Hardal MCP

The remote MCP server behind `https://mcp.usehardal.com/mcp`, a Bun + Elysia
service on Azure Container Apps (`hardal-mcp`). Users connect from Claude,
ChatGPT or any streamable-HTTP MCP client and sign in with Beacon OAuth. Each
tool in `src/tools` reads Beacon's public Reports API (`/v1`) with a token
exchanged for that user; the server never talks to Sirius or ClickHouse.

[README.md](README.md) explains connecting, and
[docs/report-coverage.md](docs/report-coverage.md) maps every tool variant to
its Beacon operation. Shared rules for all Nebula repos will live in
`AGENTS.base.md` in the `harness` repo; until it exists, this file and the docs
it links are the source.

## Commands

| Task | Command |
|---|---|
| Setup | `bun install`, `cp .env.example .env`, `bun run service-identity:generate` for a local key |
| Run | `bun run dev` (port 1922; Beacon API on 1919) |
| Lint | `bun run lint` |
| Type-check | `bun run type-check` |
| Tests | `bun test` (`tests/setup.ts` creates a throwaway signing key) |

CI also boots the server and checks `/health` (200), both protected-resource
metadata paths and that an unauthenticated `POST /mcp` gets 401; see
`.github/workflows/checks.yml`, which runs on every PR and before every deploy.

## Invariants

- Every `/mcp` request carries a Beacon access token whose audience is
  `MCP_RESOURCE`. Without one the server answers 401 with the OAuth challenge
  before doing anything else.
- The server never forwards the user's token. It introspects it, then
  exchanges it (`src/oauth/token-exchange.ts`) for a Reports API token
  (`REPORTS_API_RESOURCE`) and calls Beacon with that. MCP tokens stay out of
  the Reports API audience.
- The server authenticates to Beacon as its own service identity
  (`SERVICE_CLIENT_ID`, `private_key_jwt`). Production reads the private key
  from Key Vault (`SERVICE_PRIVATE_JWK_VAULT_URL`); only local runs use a key
  file.
- Tenants and sources are UUIDs, and every report is scoped to tenants the
  user approved at sign-in.
- Report calls are rate limited per user per replica
  (`MCP_REPORTS_RATE_LIMIT_PER_MINUTE`, minimum 2).
- Tool names and input schemas are a public contract for connected clients;
  rename or remove one only with a decision on the issue.

## Endpoints and metrics

- The HTTP endpoints are `/mcp`, `/health` and `/.well-known/*`. There is no
  Postman collection yet; the first PR that adds or changes an endpoint creates
  `postman/hardal-mcp.postman_collection.json` covering all of them.
- A tool change updates `docs/report-coverage.md` and the README tool list in
  the same PR.
- The server exports no metrics and has no dashboard JSON yet. The first change
  that needs a metric adds it and
  `docs/observability/hardal-mcp-grafana-dashboard-import.json` with its panel.

## Never do

- Log, return or put in an error message a user token, an exchanged token or
  the service private key.
- Call Sirius, ClickHouse or Beacon's internal APIs; only the `/v1` Reports API
  through the exchanged token.
- Commit a generated service key, or run `service-identity:generate` against
  production; production keys live in Key Vault.
- Point tests at a real Beacon; they stub `fetch` and Beacon's responses.
- Skip or delete a failing test to get CI green.

## Misleading areas and decisions not in the code

- This repo used to be the stdio npm package `usehardal-mcp`, and
  `package.json` still has that name. `server.json` now lists only the remote
  endpoint; nothing here publishes to npm.
- `OAUTH_ISSUER` (advertised in metadata) and `BEACON_API_URL` (where the
  server calls Beacon) are separate settings and can differ.
- The deploy workflow (`hardal-mcp-AutoDeployTrigger-*.yml`) was generated by
  Azure. It signs in with OIDC but still pushes to `hardalmcp.azurecr.io` with
  a stored registry username and password, and it deploys on every push to
  `master`.
- CI pins Bun 1.3.5; the Docker image uses `oven/bun:1.4.4`.

## Agent guardrails

`.agents/hooks/guard.mjs` blocks reading or editing real `.env` files and
network calls to the production ClickHouse gateway, proxies, nodes or Keepers.
`.agents/hooks/stop-typecheck.mjs` keeps the agent working until
`bun run type-check` passes. Both are wired up in `.claude/settings.json`,
`.codex/hooks.json` and `.cursor/hooks.json`. If a guard blocks something you
need, ask a person; don't work around it.

## Working style

- State assumptions and ask when a request can be read more than one way.
- Write the minimum code that solves the problem; no speculative options.
- Touch only what the task needs; match the existing style; mention unrelated
  problems instead of fixing them.
- Turn the task into a check (a failing test, a type error, a command) and
  loop until it passes.
